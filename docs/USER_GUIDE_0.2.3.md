# Транскрибатор 0.2.3 — руководство пользователя

Актуально для версии: **0.2.3 (build 205)**

Платформа: **Mac с Apple Silicon (M1 или новее), macOS 15 или новее**

Тип сборки: **INTERNAL / UNNOTARIZED**

## 1. Что умеет Транскрибатор

Транскрибатор локально преобразует записи встреч и речь во время созвона в
текст с таймкодами. Аудио и готовые документы остаются на вашем Mac.

Доступны два режима:

1. **Из файла** — обработка одной записи или нескольких последовательных
   частей встречи.
2. **Рилтайм** — распознавание системного звука во время встречи с небольшой
   задержкой.

Результат можно получить в трёх форматах:

- **DOCX** — документ для чтения и редактирования;
- **TXT** — простой текст с таймкодами;
- **JSON** — структурированные данные для последующей обработки.

Дополнительные возможности:

- повторная проверка пропущенных реплик;
- обработка тихих голосов;
- объединение нескольких частей встречи со сквозными таймкодами;
- разделение речи на анонимных участников: «Спикер 1», «Спикер 2» и т. д.;
- отдельное управление системным звуком и микрофоном в realtime;
- работа realtime-встречи в фоне при переключении на другое окно;
- открытие готового результата и рабочих папок в Finder.

## 2. Системные требования

Для версии 0.2.3 необходимы:

- Mac с процессором Apple Silicon: M1, M2, M3, M4 или новее;
- macOS 15 или новее;
- около 6 ГБ свободного места для приложения, моделей и рабочих файлов;
- права администратора для первого запуска текущей внутренней сборки;
- интернет только при первой загрузке моделей разделения по спикерам.

Базовая транскрибация без разделения по спикерам использует встроенные модели
и не требует токена Hugging Face.

## 3. Скачивание и установка

Актуальная версия находится на странице
[GitHub Release v0.2.3](https://github.com/ainikitadanik-commits/transcriber/releases/tag/v0.2.3).

Скачайте файл:

`Transcriber-0.2.3-build-205-INTERNAL-macOS-arm64.dmg`

Затем:

1. Дважды нажмите на скачанный DMG.
2. Перетащите `Транскрибатор.app` на ярлык **Applications**.
3. Откройте папку **Программы / Applications** и запустите Транскрибатор.
4. Если macOS заблокировала приложение, откройте **Системные настройки →
   Конфиденциальность и безопасность**.
5. Найдите сообщение о Транскрибаторе и нажмите **Всё равно открыть / Open
   Anyway**.
6. Подтвердите запуск с помощью учётной записи администратора.

Не отключайте Gatekeeper, не выполняйте команды `xattr` и не пытайтесь обходить
корпоративные ограничения MDM. Если кнопка **Всё равно открыть** недоступна,
обратитесь в IT-службу.

### Необязательная проверка файла

Опубликованная SHA-256 текущего DMG:

```text

```

## 4. Первый запуск и разрешения macOS

Транскрибатор открывается в отдельном окне приложения. Внутри используется
локальный интерфейс, доступный только на этом Mac.

Для режима **Из файла** доступ к микрофону и системному звуку не требуется.

При первом запуске режима **Рилтайм** macOS может отдельно запросить разрешения
для:

- захвата системного звука;
- доступа к микрофону, если включена опция **Добавлять мой микрофон**.

Подтвердите только те разрешения, которые нужны для выбранного сценария. Если
доступ был отклонён, его можно проверить в **Системные настройки →
Конфиденциальность и безопасность**. После изменения разрешения полностью
закройте Транскрибатор и откройте его снова.

Корпоративный профиль Mac может запрещать захват звука. Такое ограничение
может изменить только IT-служба организации.

## 5. Транскрибация записи из файла

### Быстрый сценарий

1. Откройте вкладку **Из файла**.
2. Перетащите запись в область загрузки или нажмите на неё и выберите файл.
3. Оставьте **Обработка → Автоматически**.
4. Оставьте модель **RNNT — основная**.
5. Нажмите **Начать транскрибацию**.
6. Дождитесь статуса **Готово**.
7. Нажмите **Показать в Finder** либо сохраните DOCX, TXT или JSON в выбранное
   место.

Поддерживаются распространённые аудио- и видеоформаты, включая WEBM, MP4,
WAV, MP3, M4A, FLAC, OGG и AAC.

### Несколько частей одной встречи

Если встреча разделена на несколько файлов:

1. Выберите первую часть.
2. Нажмите **Добавить следующую часть**.
3. Добавляйте файлы строго в хронологическом порядке.
4. Запустите транскрибацию.

Приложение объединит результат, а таймкоды каждой следующей части продолжатся
после предыдущей.

### Настройки обработки

**Обработка**

- **Автоматически** — рекомендуемый режим; приложение само выбирает доступный
  способ обработки.
- **Apple Silicon (MPS)** — ускорение на графических ядрах Mac.
- **Процессор (CPU)** — обычно медленнее, но может помочь при проблемах MPS.

**Модель распознавания**

- **RNNT — основная** — рекомендуемый вариант.
- **CTC — для сравнения** — альтернативная модель для проверки результата.

**Проверять пропуски повторно**

Включено по умолчанию. Помогает восстановить тихие и пропущенные реплики, но
увеличивает время обработки.

**Тихие голоса**

- **Авто** — рекомендуемый режим;
- **Вкл** — принудительно нормализовать громкость;
- **Выкл** — не применять дополнительную обработку громкости.

### Разделение записи по спикерам

1. Включите **Разделить по спикерам**.
2. Если точное количество участников известно, выберите его. В остальных
   случаях оставьте **Авто**.
3. При первом использовании подготовьте личный Hugging Face token по разделу
   7 и вставьте его в поле **Токен для загрузки моделей**.
4. Запустите транскрибацию и дождитесь загрузки модели и обработки.

Транскрибатор определяет голоса акустически. Он не получает имена из Zoom,
Teams, Яндекс Телемоста или других сервисов, поэтому использует анонимные
подписи. Подписи могут потребовать ручной проверки, особенно при перебиваниях,
фоновой речи и похожих голосах.

## 6. Транскрибация встречи в реальном времени

### Перед началом

1. Откройте вкладку **Рилтайм**.
2. Решите, нужно ли добавлять ваш микрофон.
3. Решите, нужно ли разделять участников системного звука по спикерам.
4. При первом запуске разделения по спикерам вставьте личный Hugging Face token.
5. Нажмите **Начать встречу** и подтвердите системные разрешения macOS.

### Системный звук

Системный звук включён всегда: это голоса собеседников, которые воспроизводит
Mac. При включённой опции **Разделять участников встречи** приложение пытается
акустически подписать разные голоса как «Спикер 1», «Спикер 2» и т. д.

Разделение выполняется локально и не использует каналы или имена из сервиса
видеоконференции. Кратковременная ошибка определения спикеров не должна
останавливать встречу: фрагмент продолжит распознаваться без уверенной подписи,
а в интерфейсе появится предупреждение.

### Микрофон пользователя

Опция **Добавлять мой микрофон** выключена по умолчанию. Включайте её только
если собственная речь должна попасть в транскрипцию.

Важно: Транскрибатор не может универсально узнать, нажата ли кнопка mute в
Zoom, Teams, Яндекс Телемосте, браузере или другой ВКС. Если микрофон включён в
Транскрибаторе, приложение может распознавать вашу речь, даже когда коллеги не
слышат вас из-за mute внутри ВКС.

Выбор микрофона и разделения по спикерам фиксируется при старте встречи. Во
время активной сессии переключатели недоступны. Чтобы изменить режим:

1. нажмите **Завершить встречу**;
2. дождитесь сохранения результата;
3. измените настройки;
4. начните новую realtime-сессию.

### Во время встречи

- Живой текст появляется с небольшой задержкой: GigaAM обрабатывает короткие
  накопленные фрагменты, а не непрерывный streaming-поток.
- Последний фрагмент может отображаться как черновик и уточняться.
- Можно переключиться на другую программу или закрыть окно интерфейса:
  backend продолжит встречу в фоне.
- Не выбирайте **Завершить работу / Quit** в меню приложения до окончания
  встречи.
- Снова откройте Транскрибатор, чтобы увидеть фактический таймер и накопленный
  текст.
- Кнопка **Пауза** в версии 0.2.3 ещё не работает.

### Завершение встречи

1. Вернитесь в Транскрибатор.
2. Нажмите **Завершить встречу**.
3. Подтвердите завершение.
4. Дождитесь финализации последнего фрагмента и статуса **Готово**.
5. Нажмите **Показать в Finder** или сохраните DOCX, TXT и JSON.

Не завершайте процесс приложения принудительно: последний фрагмент может не
успеть попасть в итоговые документы.

## 7. Личный Hugging Face token для спикеров

Token нужен только для первой загрузки моделей pyannote, используемых при
разделении по спикерам. Для обычного распознавания без спикеров он не нужен.

Каждому пользователю рекомендуется использовать собственный token с правом
**Read**. Не публикуйте token в чате, письме, инструкции или общем файле и не
передавайте коллегам token другого пользователя.

Подготовка:

1. Создайте или откройте личную учётную запись Hugging Face.
2. Примите условия модели
   [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0).
3. Примите условия модели
   [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1).
4. Создайте token с минимальным правом **Read**.
5. Вставьте token в скрытое поле Транскрибатора непосредственно перед первым
   запуском обработки со спикерами.

Token используется в памяти только для загрузки моделей и не сохраняется
Транскрибатором. После успешной загрузки дальнейшее разделение по спикерам
работает локально из кэша.

## 8. Где находятся записи и результаты

Все рабочие данные находятся в папке текущего пользователя:

```text
~/Library/Application Support/Транскрибатор
```

Основные подпапки:

- `input` — добавленные записи;
- `output` — готовые TXT, DOCX и JSON;
- `models` — локально загруженные модели;
- `logs` — технические журналы.

В нижней части интерфейса доступны кнопки:

- **Открыть записи**;
- **Открыть транскрипции**.

После обработки удобнее всего нажать **Показать в Finder**: приложение выделит
готовый DOCX в папке результатов.

Если результат с таким именем уже существует, Транскрибатор создаёт свободное
имя с числовым индексом. Исходный результат не заменяется автоматически.

Удаляйте ненужные записи и результаты вручную через Finder с учётом правил
работы с персональными данными вашей организации.

## 9. Приватность и работа без интернета

Локально обрабатываются и хранятся:

- исходные аудио- и видеозаписи;
- realtime-аудио;
- распознанный текст;
- DOCX, TXT и JSON;
- технические журналы.

Realtime-аудио передаётся между компонентами приложения через локальные
каналы в оперативной памяти и не сохраняется как отдельная запись встречи.

Интернет используется только для загрузки отсутствующих моделей pyannote после
того, как пользователь сам включил разделение по спикерам и ввёл личный token.
Запись и транскрипция в Hugging Face не отправляются. Собственной облачной
транскрибации, аналитики и синхронизации между устройствами в приложении нет.

## 10. Частые проблемы

### macOS не открывает приложение

Откройте **Системные настройки → Конфиденциальность и безопасность → Всё равно
открыть** и подтвердите действие администратором. Если кнопки нет, обратитесь в
IT-службу. Не отключайте системную защиту.

### Не работает системный звук или микрофон

1. Завершите активную встречу.
2. Проверьте разрешения Транскрибатора в настройках конфиденциальности macOS.
3. Полностью завершите Транскрибатор через меню приложения.
4. Откройте приложение снова и повторите проверку.

Если разрешение управляется корпоративным профилем, обратитесь в IT-службу.

### Моя речь попадает в текст при mute внутри ВКС

Завершите текущую realtime-сессию и начните новую с выключенной опцией
**Добавлять мой микрофон**. Mute сервиса ВКС и переключатель Транскрибатора —
независимые настройки.

### Не загружается модель спикеров

Проверьте, что:

- приняты условия обеих моделей pyannote;
- используется личный token с правом Read;
- Mac подключён к интернету;
- token вставлен без пробелов в начале и конце.

Не отправляйте token вместе со скриншотом ошибки.

### Спикеры определились неточно

Для файла укажите известное количество участников и попробуйте повторную
обработку. На результат влияют перебивания, эхо, фоновая речь, качество связи и
похожие голоса. Имена участников при необходимости замените вручную в DOCX.

### Обработка идёт долго или завершилась ошибкой MPS

Сначала повторите с настройкой **Автоматически**. Если ошибка сохраняется,
выберите **Процессор (CPU)**. Длинные записи, повторная проверка пропусков и
разделение по спикерам заметно увеличивают время обработки.

### Не удаётся сохранить результат

Нажмите **Показать в Finder** или **Открыть транскрипции**. Оригинальные файлы
уже находятся в папке `output`, даже если системный диалог сохранения был
закрыт. При совпадении имён приложение создаёт новый вариант с индексом.

### Realtime сообщает, что помощник захвата недоступен

Полностью завершите приложение и установите актуальную версию 0.2.3 заново.
Если сообщение осталось, приложите его текст к обращению владельцу продукта.

## 11. Обновление приложения

1. Завершите все активные обработки и realtime-встречи.
2. Закройте Транскрибатор через меню **Завершить работу / Quit**.
3. Скачайте новый DMG из официального GitHub Release.
4. Замените приложение в папке Applications новой версией.
5. Запустите приложение и при необходимости повторно подтвердите запросы
   macOS.

Обновление приложения не должно удалять папки `input`, `output` и `models`, но
перед обновлением важные результаты рекомендуется скопировать в рабочее
хранилище организации.

## 12. Известные ограничения версии 0.2.3

- Текущий DMG не нотарифицирован Apple и требует администратора при первом
  запуске.
- Поддерживаются только Mac с Apple Silicon и macOS 15 или новее.
- Realtime работает с небольшой задержкой и не является дословным streaming.
- Пауза realtime-сессии пока недоступна.
- Настройки микрофона и спикеров нельзя менять в середине активной сессии.
- Mute внутри ВКС не синхронизируется с микрофоном Транскрибатора.
- Определение спикеров акустическое и может ошибаться; имена людей не
  определяются.
- При одновременной речи нескольких людей часть слов или атрибуция спикера
  могут быть неточными.
- Исходный realtime-звук не сохраняется отдельным аудиофайлом.

## 13. Как отправить обратную связь

При сообщении о проблеме укажите:

1. версию приложения — 0.2.3;
2. модель Mac и версию macOS;
3. режим — **Из файла** или **Рилтайм**;
4. какие настройки были включены;
5. точный текст ошибки;
6. повторяется ли проблема после перезапуска;
7. примерный момент встречи, где возникла ошибка.

Не прикладывайте секретный Hugging Face token. Запись или транскрипцию
отправляйте только если это разрешено правилами вашей организации.
