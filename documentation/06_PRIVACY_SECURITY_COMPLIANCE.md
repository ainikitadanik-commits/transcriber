# Приватность, безопасность и соответствие

Статус: обязательные ограничения
Актуально на: 2026-07-28

## Модель доверия

Доверенная зона — текущая учётная запись macOS пользователя и установленное
приложение. Hugging Face используется только как источник файлов моделей,
которые пользователь имеет право получить. Это не сервис транскрибации.

## Классы данных

| Данные | Чувствительность | Хранение | Сеть |
| --- | --- | --- | --- |
| исходные аудио/видео | высокая | `input/` | запрещена |
| realtime PCM | высокая | только RAM | запрещена |
| TXT/JSON/DOCX | высокая | `output/` | запрещена |
| временные WAV/чанки | высокая | временный каталог | запрещена, удаляются |
| HF token | секрет | только память процесса | только Hugging Face при загрузке |
| модели | сторонние артефакты | Resources/cache | разрешена загрузка модели |
| логи | потенциально чувствительные | `logs/` | запрещена |

## Обязательные privacy-инварианты

| ID | Инвариант |
| --- | --- |
| SEC-001 | Flask слушает только `127.0.0.1` |
| SEC-002 | Записи и текст не передаются в Hugging Face |
| SEC-003 | Собственной телеметрии и аналитики нет |
| SEC-004 | `HF_HUB_DISABLE_TELEMETRY=1` устанавливается runtime |
| SEC-004A | `PYANNOTE_METRICS_ENABLED=0` устанавливается до импорта `pyannote.audio` |
| SEC-005 | `HF_TOKEN` удаляется из environment до ASR |
| SEC-006 | Token не пишется в `.env`, config, URL, CLI history или log |
| SEC-007 | После получения моделей включаются `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1` |
| SEC-008 | Realtime PCM передаётся только по локальным pipes и не пишется на диск |
| SEC-009 | Открытие папок ограничено allowlist |
| SEC-010 | Пользовательские данные устанавливаются в user-writable path |

Нарушение любого инварианта — блокирующий дефект релиза.

## Сетевая политика

Базовая файловая транскрибация без diarization не требует pyannote models,
HF token или сети и использует bundled GigaAM offline.

Единственный разрешённый сетевой сценарий относится к явно включённой
diarization:

1. пользователь принимает условия нужной модели;
2. вводит личный Read token;
3. приложение проверяет локальный snapshot;
4. отсутствующая модель скачивается с Hugging Face;
5. token удаляется;
6. runtime переключается в offline mode;
7. начинается обработка записи.

Все иные сетевые интеграции требуют отдельного ADR, threat review и явного
пользовательского решения. Добавление telemetry «по умолчанию» запрещено.

## Секреты

- UI-поле токена должно быть скрытым;
- token не возвращается в job status;
- ошибки не должны содержать token;
- тесты должны проверять отсутствие token в state/environment после загрузки;
- документация не должна советовать отправлять token в чат или сохранять его в
  проекте.

## macOS-разрешения

Internal candidate реализует:

- microphone — для голоса пользователя;
- system audio — через private Core Audio Tap без Screen Recording.

Core Audio Tap и отдельный microphone-контур реализованы, но ещё не прошли
signed acceptance на целевой no-admin учётной записи. Не подтверждены оба
штатных user prompts, одновременный ненулевой PCM и поведение под MDM.
[ADR-013](11_ARCHITECTURE_DECISIONS.md) остаётся `Proposed`, а FR-RT-001 —
`BLOCKED`.

Разрешения должны принадлежать одной постоянной подписанной идентичности:
`com.ainikitadanik.transcriber`. Изменение bundle ID приведёт к повторным
запросам и запрещено без миграционного решения. Ad-hoc CDHash не считается
постоянной release identity.

Приложение не обходит MDM/PPPC. Если корпоративный профиль запрещает audio
capture, требуется изменение профиля владельцем IT; отсутствие admin-прав у
пользователя не должно маскироваться как исправимый локально дефект.

## Локальное хранение и удаление

Пользователь контролирует `input/` и `output/` через Finder. Автоматическое
удаление финальных результатов без явного выбора не допускается.

Требуют решения до внешнего релиза:

- срок и ротация логов;
- команда полного удаления приложения и данных;
- политика очистки брошенных upload job directories;
- исключение чувствительного текста из exception/log output.

## Поставка сторонних компонентов

- GigaAM закреплён на проверенном commit;
- pyannote модели не входят в bundle; при включении diarization их загружает
  сам пользователь после принятия условий;
- FFmpeg в product `.app` собирается в минимальной конфигурации
  LGPL-2.1-or-later, без network/GPL/nonfree;
- лицензии фактически включённых Python-пакетов извлекаются из runtime;
- архив исходников FFmpeg, LGPL и configuration поставляются рядом.

Компонентная ведомость должна формироваться заново для каждого релиза; версии
из текущего файла не считаются вечными.

## Нерешённая юридическая граница

До внешнего публичного выпуска необходимо определить:

- юридического правообладателя собственного кода;
- лицензию или пользовательское соглашение;
- допустимый контур распространения;
- требуемые уведомления о моделях и зависимостях.

Документ фиксирует технические ограничения и не заменяет юридическое
заключение.

## Проверки перед релизом

1. Поиск возможных секретов в tracked files и артефакте.
2. Проверка binding на loopback.
3. First-run download с тестовым личным token.
4. Подтверждение удаления token из процесса.
5. Offline повторная обработка.
6. Сетевой контроль во время ASR.
7. Проверка отсутствия исходного realtime PCM после Stop.
8. Актуализация component ledger и лицензий.
9. Проверка логов на отсутствие токена и пользовательского текста сверх
   необходимой диагностики.
