# Документация проекта «Транскрибатор»

Статус: канонический индекс
Актуально на: 2026-08-04
Базовая версия продукта: 0.2.2

## Назначение комплекта

Этот каталог фиксирует продуктовый и технический курс «Транскрибатора».
Перед существенной разработкой исполнитель должен читать не весь репозиторий,
а этот индекс и документы, перечисленные для соответствующего типа задачи.

Документация различает:

- **текущее состояние** — подтверждено кодом, тестами или сборочными файлами;
- **зафиксированное решение** — целевое правило, которое нельзя менять попутно;
- **план** — согласованное направление, но ещё не реализованная возможность;
- **открытый вопрос** — решение пока не принято, его нельзя домысливать.

## Иерархия решений

Если источники противоречат друг другу, действует следующий порядок:

1. последнее явно одобренное решение в
   [11_ARCHITECTURE_DECISIONS.md](11_ARCHITECTURE_DECISIONS.md);
2. продуктовые принципы из [01_PRODUCT_VISION.md](01_PRODUCT_VISION.md);
3. требования из [02_SCOPE_AND_REQUIREMENTS.md](02_SCOPE_AND_REQUIREMENTS.md);
4. специализированная спецификация из этого каталога;
5. существующий код и тесты как свидетельство текущей реализации;
6. старые материалы в `docs/`, `README.md` и release notes.

Код не меняет целевой курс сам по себе. Если реализация расходится со
спецификацией, это дефект, технический долг или основание для отдельного
решения, но не автоматическая новая норма.

## Правила изменения документации

1. Значимое изменение сначала описывается как intent, scope и критерии приёмки.
2. Изменение постоянного контракта оформляется записью ADR до или вместе с кодом.
3. Требование получает стабильный идентификатор; идентификаторы не
   переиспользуются для другого смысла.
4. Нереализованная возможность не описывается как готовая.
5. Неизвестные значения остаются открытыми вопросами.
6. При изменении JSON-контракта повышается `schema_version` и описывается
   совместимость.
7. При изменении bundle ID, путей данных, сетевой модели или приватности
   требуется отдельное одобрение.
8. Один pull request или коммит должен обновлять код, тесты и затронутые
   канонические документы согласованно.

## Состояние прежних документов

Файлы `README.md`, `CHANGELOG.md` и каталог `docs/` остаются полезными
пользовательскими и историческими материалами. Они не удалены и не перенесены,
чтобы не ломать ссылки и сборку. При расхождении целевого курса приоритет имеет
этот комплект; пользовательские документы должны быть синхронизированы перед
следующим релизом.
