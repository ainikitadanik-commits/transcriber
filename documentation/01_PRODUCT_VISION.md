# Видение продукта

Статус: зафиксированный вектор
Актуально на: 2026-07-20

## Продукт

«Транскрибатор» — локальное macOS-приложение для преобразования записей рабочих
встреч и захватываемого во время встречи звука в удобную текстовую
транскрипцию. Основная ценность — рабочий результат без передачи записей,
текста и промежуточных данных в облачный сервис транскрибации.

## Пользователи

Основная аудитория:

- пользователь Mac на Apple Silicon;
- коллега без прав администратора;
- пользователь, которому нужен простой запуск из Finder;
- пользователь, работающий с внутренними или чувствительными записями;
- технический пользователь, которому дополнительно нужен CLI и JSON.

## Основные задачи пользователя

1. Выбрать один файл или последовательность частей встречи.
2. Получить читаемые TXT и DOCX, а также структурированный JSON.
3. При необходимости разделить реплики по условным спикерам.
4. Понять ход обработки и получить понятную ошибку.
5. Найти и удалить локальные исходники и результаты.
6. В перспективе запустить near-real-time режим во время онлайн-встречи.

## Продуктовое обещание

- записи и результаты обрабатываются локально;
- после первоначального получения разрешённых моделей обработка возможна без
  сети;
- интерфейс доступен только на текущем Mac;
- приложение не требует администраторских прав;
- запуск и штатное завершение не требуют Terminal;
- результат имеет стабильный машинно-читаемый контракт;
- ограничения и незавершённые функции показаны честно.

## Неизменные принципы

### P-01. Local first

Аудио, видео, PCM, транскрипции и пользовательские результаты не отправляются
во внешние сервисы.

### P-02. Простота для коллеги

Основной путь — установленное `.app`, открываемое двойным нажатием. CLI и
внутренний веб-сервер являются техническими механизмами, а не обязательными
шагами пользователя.

### P-03. Приватность по архитектуре

Сеть используется только для явно описанного получения моделей. Токен не
сохраняется приложением. Локальный сервер слушает только `127.0.0.1`.

### P-04. Один устойчивый продукт, а не набор скриптов

Постоянны имя, bundle ID, путь пользовательских данных, форматы результатов и
правила релиза. Изменять их можно только через ADR и миграционный план.

### P-05. Проверяемое качество

Готовность функции подтверждается тестами и приёмочным сценарием на реальном
аудио. Наличие UI или кода без end-to-end проверки не считается готовностью.

### P-06. Честные статусы

Realtime-захват и realtime-распознавание — разные этапы. Захват PCM не должен
выдаваться за готовую транскрипцию.

### P-07. Минимальная внешняя зависимость

Не добавлять облачную аналитику, удалённое хранилище, серверную обработку или
обязательную учётную запись приложения без отдельного продуктового решения.

## Текущий продуктовый контур

Подтверждено в версии 0.2.3:

- файловая транскрибация через GigaAM RNNT или CTC;
- длинные записи, несколько последовательных частей;
- TXT, JSON schema 1.3 и DOCX;
- опциональная diarization через pyannote;
- восстановление подозрительных пропусков;
- нормализация тихого аудио;
- MPS с fallback на CPU;
- отдельное окно macOS на базе локального WebKit UI и CLI;
- постоянное macOS `.app` с Dock/menu bar управлением;
- фоновая realtime-транскрибация системного звука и опционального микрофона;
- акустическое разделение realtime-системного звука по спикерам;
- финализация realtime-сессии в TXT, JSON и DOCX.
- отказоустойчивое realtime-разделение: ошибка одного окна не останавливает
  распознавание;
- collision-safe комплекты результатов и показ готового DOCX в Finder.

Ещё не готово как продуктовая функция:

- подписанный Developer ID и нотариализованный внешний релиз.

## Явно вне текущего вектора

- облачная транскрибация;
- централизованное хранение встреч;
- совместное редактирование;
- автоматическая идентификация людей по именам;
- субтитры как обязательный выход;
- публичная трансляция живого текста;
- поддержка Windows, Linux и Intel Mac без отдельного решения.

## Метрики успеха

До появления измеренной базы значения не выдумываются. Продукт должен
накапливать проверяемые показатели:

- доля успешно обработанных репрезентативных записей;
- медианное отношение времени обработки к длительности записи на целевых Mac;
- число критических пропусков и дубликатов на контрольном наборе;
- доля установок, прошедших без ручной помощи;
- фактическая задержка near-real-time режима;
- отсутствие обнаруженной передачи пользовательского аудио и текста наружу.
