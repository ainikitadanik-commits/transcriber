# UX-спецификация

Статус: нормативный пользовательский контракт
Актуально на: 2026-07-20

## Принципы

- основной сценарий понятен без Terminal;
- пользователь всегда видит, что выполняется локально;
- незавершённый realtime не выглядит готовой функцией;
- ошибки объясняют действие, а не только техническую причину;
- продвинутые параметры не мешают базовому сценарию;
- пользователь управляет своими файлами через Finder.

## Точки входа

Приоритет:

1. `Транскрибатор.app`;
2. Finder launcher для legacy/internal поставки;
3. web URL, открываемый приложением;
4. CLI для разработки и автоматизации.

Новая пользовательская инструкция не должна возвращать Terminal как основной
путь после готовности `.app`.

## Сценарий файловой транскрибации

1. Открыть приложение.
2. Оставить режим «Из файла».
3. Перетащить или выбрать запись.
4. При необходимости добавить следующие части в правильном порядке.
5. Оставить безопасные значения по умолчанию или раскрыть настройки.
6. Нажать запуск.
7. Видеть текущий этап и ориентировочный прогресс.
8. Получить явный статус «готово».
9. Скачать TXT/JSON/DOCX или открыть папку результатов.

## Значения по умолчанию

- device: `auto`;
- model: RNNT;
- gap recovery: включено;
- audio enhancement: `auto`;
- diarization: выключена;
- speaker count: пусто;
- batch size в UI: 2.

Изменение default считается продуктовым решением и требует оценки качества и
времени обработки.

## Настройки

Пользовательский язык:

- «Автоматически / MPS / CPU», а не внутренние детали PyTorch;
- «RNNT / CTC» сопровождаются объяснением, что RNNT — основной выбор;
- «Проверять пропуски повторно» сообщает о росте времени обработки;
- «Тихие голоса: Авто / Вкл / Выкл»;
- «Разделить по спикерам» не обещает определение имён;
- число участников доступно только вместе с diarization;
- HF token объясняется как разовый доступ к моделям, а не к записи.

## Состояния файловой задачи

| Stage | Пользовательский смысл |
| --- | --- |
| `uploading` | сохраняются выбранные локальные части |
| `preparing` | проверка и нормализация аудио |
| `downloading_models` | получение отсутствующей разрешённой модели |
| `loading_model` | локальная загрузка ASR |
| `transcribing` | распознавание |
| `recovery` | повторная проверка пропусков |
| `diarization` | разделение по условным спикерам |
| `exporting` | создание файлов |
| `done` | все результаты готовы |
| `error` | задача остановлена, показано действие |

Процент ориентировочный и показывает 100% только после успешного создания всех
выходов.

## Требования к ошибкам

Сообщение должно содержать:

1. что не получилось;
2. наиболее вероятную понятную причину;
3. конкретное действие пользователя;
4. без токенов, tracebacks и внутренних путей, если они не нужны.

Обязательные отдельные случаи:

- неподдерживаемый формат;
- файл отсутствует;
- FFmpeg отсутствует;
- MPS недоступен;
- модель отсутствует локально;
- Hugging Face недоступен;
- не приняты условия gated model / ошибочный token;
- уже идёт другая задача;
- нет macOS-разрешения;
- capture helper не собран;
- экспорт не завершён.

## Realtime UX

Экран должен отдельно показывать:

- system audio: ожидаем / есть звук / нет звука / ошибка;
- microphone: выключен / ожидаем / есть звук / нет звука / ошибка;
- явный переключатель добавления микрофона, выключенный по умолчанию;
- предупреждение, что mute внутри ВКС не синхронизируется универсально;
- состояние разрешений;
- таймер;
- состояние capture;
- состояние ASR;
- provisional и committed текст;
- фактическое предупреждение о задержке.

Start нельзя объявлять готовым к транскрибации, если подключён только capture.

## Управление данными

- «Открыть записи» открывает только `input`;
- «Открыть транскрипции» открывает только `output`;
- удаление выполняется пользователем в Finder;
- приложение не должно иметь endpoint для произвольного пути;
- при будущем «Удалить всё» требуется явное подтверждение и отдельная
  спецификация.

## Доступность и локализация

Текущий основной язык — русский. Новые элементы должны:

- иметь читаемый текстовый label;
- не полагаться только на цвет;
- сохранять работу с клавиатурой;
- не содержать необъяснённых англоязычных ошибок;
- учитывать длинные русские строки.

Полная локализация на другие языки не входит в текущий scope.

## Визуальная система и адаптивность

Детальный контракт закреплён в
[15_UI_POLISH_SPECIFICATION.md](15_UI_POLISH_SPECIFICATION.md).

- основной glass shell не шире 900 px;
- внешний шрифт, icon CDN и иные сетевые UI-зависимости запрещены;
- файловый и realtime-разделы используют общие tokens, controls и Finder panel;
- контрольные ширины: 1440, 1280, 1024, 820, 640 и 480 px;
- horizontal overflow недопустим;
- reduced-motion отключает постоянные декоративные анимации.

Длинное имя файла сокращается только визуально: basename и extension
показываются раздельно, extension остаётся видим, а полное имя доступно через
tooltip и accessible name. Исходное `File.name` в FormData не меняется.

Пока FR-RT-003/004 остаются `PLANNED`, realtime UI называется capture
diagnostic: Start проверяет захват, Pause disabled с явной пометкой, live-text
panel не обещает работающую расшифровку или экспорт.
