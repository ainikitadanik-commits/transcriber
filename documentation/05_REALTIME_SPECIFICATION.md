# Спецификация near-real-time режима

Статус: целевая спецификация, реализация частичная
Актуально на: 2026-08-03

## Цель

Во время онлайн-встречи пользователь запускает локальный захват системного
звука и микрофона, видит пополняющийся текст, а после завершения получает TXT,
JSON и DOCX. Исходный realtime PCM не сохраняется на диск.

GigaAM не является streaming ASR. Поэтому термин **near-real-time** обязателен:
короткие накопленные окна распознаются последовательно с измеряемой задержкой.

## Текущая граница готовности

Реализовано во внутреннем candidate:

- UI режима и состояния Start/Pause/Stop;
- native capture через private Core Audio Tap и отдельный AVAudioEngine
  microphone-контур;
- отдельные system/microphone потоки;
- преобразование в `pcm_s16le`, mono, 16 кГц;
- локальные pipes;
- ограниченные RAM-буферы до 120 секунд на источник;
- события о разрешениях и наличии аудио;
- API start/status/stop;
- bounded scheduler коротких перекрывающихся окон;
- локальный GigaAM adapter, overlap dedup и committed/provisional state;
- финализация и локальный TXT/JSON/DOCX export без записи исходного PCM.

Не подтверждено:

- live signed TCC запуск двух источников на чистом corporate no-admin Mac;
- continuity разрешений после restart/update с постоянной Developer ID
  identity;
- 30-минутная dual-source встреча и latency benchmark;
- пауза как полноценная семантика с продолжением сессии;
- MDM denial на реальном управляемом устройстве.

## Состояния сессии

Целевая машина состояний:

```text
idle -> requesting_permissions -> capturing <-> paused
capturing|paused -> finalizing -> done
любое активное состояние -> error
error|done -> idle
```

Текущий manager использует более узкие `idle`, `starting`, рабочее состояние и
ошибку. Расширение должно сохранить понятный API-контракт.

## Источники

### System

Системный звук приложений встречи через private/global Core Audio Tap с
исключением собственного процесса.

### Microphone

Голос пользователя через микрофон. Источник опционален и выключен по
умолчанию. В таком режиме native helper не открывает AVAudioEngine, не
запрашивает microphone permission и не создаёт microphone PCM pipe.

Состояние mute внутри ВКС нельзя определять универсально: сервисы не публикуют
общий контракт, а приложение встречи может продолжать держать устройство
открытым после нажатия mute. Поэтому включение микрофона управляется явным
переключателем Транскрибатора и не заявляется как синхронизированное с
Яндекс Телемостом, Zoom, Teams или браузерной ВКС.

Источники хранятся раздельно до этапа ASR. Сведение в один поток не принимается
по умолчанию: раздельность позволяет диагностировать отсутствие источника,
управлять уровнем и в будущем улучшать атрибуцию.

## Аудиоконтракт

Для каждого источника:

- encoding: `pcm_s16le`;
- sample rate: `16000`;
- channels: `1`;
- sample width: `2 bytes`;
- транспорт: anonymous local pipe;
- persistence: RAM only;
- максимальный rolling buffer: 120 секунд.

## Целевой оконный алгоритм

Параметры до бенчмарка считаются настраиваемыми, а не окончательными:

- ASR window MUST быть не длиннее 25 секунд;
- окна SHOULD иметь небольшой overlap;
- scheduler MUST различать provisional и committed текст;
- повтор на границе MUST удаляться детерминированным алгоритмом;
- уже committed текст MUST не исчезать при следующем окне;
- временная ошибка окна MUST не завершать всю встречу;
- фактическая задержка MUST измеряться отдельно на MPS и CPU.

Точные window/overlap/commit horizon нельзя закреплять без контрольных
измерений. Они перечислены в открытых вопросах.

## Объединение двух источников

Первый realtime-MVP должен выбирать одну из двух реализаций через ADR:

1. отдельное ASR каждого источника с последующим временным merge;
2. контролируемое микширование с сохранением source availability metadata.

До решения нельзя случайно реализовать один вариант как «очевидный». Отдельное
ASR лучше сохраняет происхождение реплики, но примерно удваивает вычисление.

## Живой текст

UI должен различать:

- provisional — последний изменяемый фрагмент;
- committed — подтверждённый неизменяемый текст;
- warning — один источник отсутствует или задержка растёт;
- error — захват или ASR остановлены.

Интерфейс не должен показывать заглушку как распознанный текст.

## Pause и Stop

### Pause

- прекращает добавление новых PCM в ASR;
- не удаляет committed текст;
- не закрывает сессию;
- возобновление продолжает монотонную временную шкалу либо фиксирует gap.

Точная семантика захвата во время pause требует ADR.

### Stop

1. прекращает захват;
2. финализирует неполное окно;
3. завершает deduplication;
4. строит общий document object;
5. записывает TXT, JSON, DOCX;
6. очищает PCM и временные данные;
7. показывает ссылки на результаты.

## Realtime JSON

До реализации нельзя объявлять новую schema готовой. Целевое расширение должно
как минимум фиксировать:

- `processing.mode = near_realtime`;
- источники и их availability;
- параметры окон;
- измеренную latency;
- список предупреждений/потерь источника;
- сегменты итоговой транскрипции.

Решение: расширить 1.x или создать 2.0 — открыто до реализации.

## Критерии приёмки realtime-MVP

Зелёные unit/integration tests подтверждают внутренний контур, но не заменяют
signed TCC acceptance.

1. 30-минутная тестовая встреча проходит без роста RAM сверх установленных
   границ.
2. Оба источника обнаруживаются и раздельно диагностируются.
3. Текст пополняется во время речи.
4. На стыках нет систематического размножения фраз.
5. Committed текст не откатывается.
6. Временная ошибка одного окна видна и не уничтожает сессию.
7. Stop создаёт валидные TXT, JSON, DOCX.
8. После завершения PCM и временные аудиофайлы отсутствуют.
9. Сетевой мониторинг не обнаруживает передачу аудио или текста.
10. Проверены MPS и CPU на целевом Mac.

## Вне первого realtime-MVP

- online-diarization;
- определение имён;
- трансляция текста другим участникам;
- запись исходного realtime-аудио;
- синхронизация между устройствами;
- гарантированная дословная стенограмма.
